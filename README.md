# فلوسي · Flousy

**اعرف فلوسك راحت فين، من غير تعقيد.**

فلوسي دفتر فلوس شخصي بالعربي: تسجل اللي وصلك، يتوزع على صناديقك، وتكتب صرفت كام وفين. معمول عشان تسجيل المصروف ياخد ثواني، سواء من الموبايل أو الكمبيوتر.

## الفكرة ببساطة

أي دخل جديد بيتقسم افتراضيًا على:

| الصندوق | النسبة الافتراضية | معمول لإيه؟ |
| --- | --- | --- |
| صدقة | 10% | تخصص جزء لله وتتابع اللي طلع واللي لسه موجود. تقدر تزود النسبة أو تقللها حسب قدرتك. |
| الادخار | 30% | تحوش للمستقبل وتشوف إجمالي اللي خصصته والمتبقي منه. |
| المصاريف | 60% | الفلوس المتاحة لمصاريفك اليومية. |

مثال: دخلت 1,000 جنيه → 100 صدقة، و300 ادخار، و600 مصاريف. النسب دي اختيار افتراضي قابل للتعديل، مش إلزام. مجموع نسب الصناديق لازم يبقى 100%، والتغيير بيطبق على الدخل الجديد؛ العمليات القديمة بتحتفظ بتوزيعها.

## تستخدمه إزاي؟

1. افتح بطاقة «اللي وصلني» وسجل المبلغ. مصدر الفلوس اختياري.
2. افتح الصندوق اللي صرفت منه، اكتب المبلغ ووصف بسيط، واضغط Enter. التاريخ متاح للاختيار.
3. شوف المتبقي قدامك، وافتح السجل لو عايز تراجع أو تبحث عن عملية.
4. في آخر اليوم أو الشهر، اختار الفترة واطبع ملخصك أو السجل بالتفصيل.

## موجود فيه إيه؟

- صناديق تحت بعض، بأسماء وألوان وترتيب ونسب قابلة للتعديل؛ وتقدر تضيف صناديق لحد 12 صندوق.
- تسجيل سريع مع حفظ محلي للعمليات المعلقة ومزامنة في الخلفية للحساب المسجل. لو حصل تعارض بين جهازين، بيطلب منك تراجعه.
- لو المبلغ أكبر من رصيد الصندوق، بيعرض عليك تغطية الفرق من صندوق تاني تختاره. العملية الجديدة ما بتعملش رصيد سالب.
- تحويلات بين الصناديق، وإجمالي التمويل منفصل عن المتبقي؛ الصرف ما بيمسحش أساس الصندوق.
- صدقات خارجية مستقلة عن فلوسك، ما بتزودش دخلك ولا بتقلل رصيدك.
- سجل بالشهور وبحث في الفئات، ومراجعة الفرق بين الرصيد المسجل والفلوس الموجودة معاك فعلًا.
- ملخص يومي أو شهري للطباعة على A4، وزر مستقل لطباعة سجل العمليات بجدول ممتد على الصفحات. تقدر تختار «حفظ PDF» من نافذة الطباعة.
- أربع ثيمات مختلفة، منها الفاتح والداكن، وواجهة عربية RTL مناسبة للموبايل.
- صفحة حساب لتعديل الاسم، وتصدير واستيراد JSON لنقل البيانات، وتصفير البيانات أو حذف بيانات التطبيق بتأكيد `0000`.
- متابعة بسيطة للديون وهدف الادخار؛ تسجيل سداد الدين هنا ما بيحركش فلوس الصناديق تلقائيًا.
- وضع ضيف محلي على الجهاز. تصدير نسخة احتياطية مهم؛ مسح بيانات المتصفح ممكن يمسح بيانات الضيف.

## حالة التشغيل بوضوح

| الجزء | حالته الحالية |
| --- | --- |
| واجهة التسجيل والصناديق والسجل والطباعة | منفذة في نسخة Sites الحالية |
| حفظ الحساب الحالي | Cloudflare D1 مع هوية ChatGPT الخاصة بالمنصة |
| مشروع Supabase باسم Flousy | موجود وسليم؛ تم التحقق يوم 17 أكتوبر 2026 |
| حفظ Supabase | منفذ للنسخة المستقلة وجداولها أُنشئت؛ نقل الدفتر القديم باستيراد JSON من صاحبه، ولم يُنفّذ تلقائيًا |
| تسجيل الدخول المباشر بجوجل | مسارات PKCE جاهزة في standalone؛ مزود Google ورابط الإنتاج لسه محتاجين إعداد واختبار |
| التقرير اليومي بالإيميل | القالب وPDF وإعداد الوقت موجودين؛ الإرسال والجدولة مش شغالين لحد ربط المرسل واختبار المسار كامل |
| تطبيق iOS وAndroid | خطة مستقبلية موثقة، مش تطبيق منشور |

النسخة الحالية خاصة بصاحبها. وجود رابطها هنا ما بيخليهاش متاحة لأي حد. حذف الحساب الحالي بيحذف بيانات التطبيق، مش حساب Google أو ChatGPT نفسه. تنسيق A4 معمول في الكود، لكن عدد الصفحات الفعلي محتاج مراجعة على المتصفح والطابعة اللي هتستخدمهم.

## تسجيل الدخول المستقل بـSupabase

مجلد [standalone](standalone/README.md) فيه نسخة Next.js مستقلة، بتستخدم نفس الواجهة والمنطق المالي، وتضيف Google والبريد وكلمة مرور وحفظ Postgres بسياسات RLS. كود الدخول والجداول جاهزين؛ تفعيل Google وإعداد رابط الإنتاج وتجربة OAuth حقيقية لسه مطلوبين. النسخة القديمة على Sites تفضل منفصلة ببياناتها.

```sh
pnpm install --frozen-lockfile
pnpm --dir standalone dev
pnpm --dir standalone build
```

راجع ملف الإعدادات النموذجي `standalone/.env.example` ودليل النسخة قبل التشغيل. للنشر على Vercel اختار Root Directory = `standalone`.

## للمطورين

الكود React 19 وTypeScript، ببنية App Router. التشغيل والبناء الفعلي باستخدام **Vinext + Vite** على Cloudflare Workers، والتخزين الحالي **D1 SQLite**. وجود dependency باسم Next.js ما معناهش إن النسخة دي تشتغل مباشرة بـ `next start` أو تتنشر على Vercel من غير تكييف.

### تشغيل محلي

تحتاج Node.js بإصدار `22.13.0` أو أحدث، ونسخة pnpm المحددة في `package.json`.

</div>

```sh
pnpm install --frozen-lockfile
pnpm dev
```

<div dir="rtl">

في بيئة portable، التطوير المحلي بيستخدم محاكاة تسجيل دخول على loopback فقط. المحاكاة مش جزء من الإنتاج. تشغيل حفظ الحساب محليًا محتاج إعداد D1 وتطبيق migration؛ التفاصيل في [دليل التطوير](docs/DEVELOPMENT.md). وضع الضيف لا يحتاج قاعدة بيانات سحابية.

للتأكد من الأنواع والبناء:

</div>

```sh
pnpm exec tsc --noEmit
pnpm build
```

### ملاحظات وسداد الديون
زر «+ إضافة ملاحظة» تحت المبلغ بيفتح خانة اختيارية للدخل أو المصروف. لسداد دين عليك، اختار الدين من كراسة الصندوق، أو اختار المبلغ والصندوق والتاريخ من إعدادات الديون؛ العملية بتخصم من الصندوق والدين مع بعض. تعديلها أو حذفها من التاريخ بيحدّث الاتنين. المدفوعات القديمة محفوظة كمتابعة من غير خصم جديد.
